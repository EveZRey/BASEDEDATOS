1.1 Aspectos Básicos de las Bases de Datos

¿Qué es un Dato?

Representación de hechos, conceptos o instrucciones organizados de forma que se puedan procesar, interpretar o comunicar por medios humanos o automáticos. Representación de caracteres o cantidades analógicas con un significado.
Tipos: Cuantitativos (Cantidades, medir) y Cualitativos (Cualidades, no medibles/contabilizables).

¿Qué es Información?

Conjunto de datos con un significado, que reduce o aumenta de algo. Comprende los datos y brinda conocimientos que se utiliza en la toma de decisiones. Son datos procesados para ser entendidos.

Sistemas y Sistemas de Información

  • ¿Qué es un Sistema? Conjunto de elementos relacionados entre sí para satisfacer un propósito específico. (Objetivos, Elementos, Asociación, Alcance, Restricciones).
  • Sistema de Información: Conjunto de elementos interrelacionados con objetivo de administración y control de datos. (Elementos: Datos, SW, HW, RRHH).
  • Actividades: Entidades externas (cuadrado), Proceso (círculo), Almacén de datos (cilindro), Flujos (flechas).
  • Tipos: Transaccionales, Ejecutivos, Estratégicos, Apoyo a la toma de decisiones.

Base de Datos (BD) y Propiedades

Colección de datos organizados y relacionados entre sí. Propiedades implícitas:

  1. Representa algún aspecto del mundo real.
  2. Conjunto de datos lógicamente coherente con significado inherente.
  3. Diseñada, construida, poblada con datos para un objetivo específico.

Características del Enfoque de Base de Datos

  • Someter a procesamiento datos conocidos y obtener nuevos.
  • Naturaleza auto descriptiva. (Catálogo del sistema = Definición de estructura).
  • Separación entre los programas y los datos (Independencia).
  • Multiusuario (Concurrencia) y Múltiples vistas. Procesamiento de transacciones.
  • Ventajas: Datos organizados, Redundancia Controlada, Consistencia, Seguridad.

1.1.3 Usuarios y 1.1.4 Ciclo de Vida

Usuarios de la Base de Datos

  • DBA (Administrador de BD): Supervisa y controla recursos. (Diseño, Seguridad, Copias, Mantenimiento).
  • Diseñador de la BD: Identifica datos a almacenar. Define la estructura apropiada (Modelos).
  • Analistas y programadores: Diseñan e implementan las aplicaciones para acceder a la BD.
  • Usuarios Finales: Esporádicos, Paramétricos/Simples (Operaciones enlatadas), Avanzados, Autónomos (no saben de la BD).

Fases de desarrollo de las BD (Ciclo de Vida)

Mini Mundo // Realidad, necesidad o problemática -> Requerimientos de BD.

  1. Recolección y análisis de requerimientos
  2. Diseño Conceptual: => Esquema Conceptual (Independencia del SGBD).
  3. Diseño Lógico: Esquema lógico / Refinación. (Dependencia del SGBD).
  4. Diseño Físico: Esquema interno // SQL.

Nota: Herramientas CASE. Necesidad de Análisis (¿Qué?), Diseño (¿Cómo?). Ejemplos: Genexus, IBM Workbench, ERWIN.

1.2 SGBD, Módulos Componentes y Lenguajes

Sistema Gestor de Datos (SGBD)

Sistema de software de propósito general. Conjunto de programas para crear y mantener una BD.
Características: Control de redundancia, concurrencia, restricción de accesos, almacenamiento persistente, diferentes interfaces, integridad, respaldo/recuperación.
Desventajas: Costos, infraestructura robusta, capacitación, mayor complejidad (muchos vínculos), búsquedas más lentas.

Arquitectura Interna (Motor SGBD)

Usuarios -> Formularios / Apps Front-end / Interfaz SQL -> Comandos SQL

Procesamiento: Ejecutor del plan, Evaluador Operadores, Parser, Optimizador.

Físico: Admin de transacciones, Archivos/métodos de acceso, Admin de páginas, Admin de espacio en disco, Admin de recuperación, Bitácora.

Almacenamiento: Catálogo del sistema -> Archivo de datos / Archivo de índices.

Compilador y Optimizador

  • Compilador: Analiza SQL (Léxico, sintácticas, semánticas). Transforma SQL -> Árbol inicial => Árbol canónico.
  • Optimizador de consultas: Analiza y transforma una consulta en una secuencia eficiente. Utiliza Heurísticas/Reglas algebraicas y evalúa Costos (Metadatos, CPU, Disco).

Lenguaje SQL

Lenguaje declarativo de alto nivel.

  • DDL: Lenguaje de Definición de datos (Create table...).
  • DML: Lenguaje de Manipulación de datos (Insert, Select...).
  • CTL / TCL: Control de transacciones (Commit).
  • DCL: Control de acceso a datos. (VDL: Vistas, SDL: Almacenamiento).

Metadatos y Transacción

Transacción: Modificar el valor de un dato.
Metadatos: Descripción de un dato. Contiene la Granularidad (tipo, longitud, restricciones). El Catálogo del sistema es el conjunto de Metadatos.

1.3 Arquitectura de 3 Niveles y Sistemas de BD

Sistema de Base de Datos (SBD)

Conjunto de recursos para manipular la BD.
Estructura: Usuarios <--> Programas de Aplicación <--> SGBD <--> BD almacenada.

Arquitectura de Tres Niveles (ANSI-SPARC, 1975)

Objetivo: Formar una separación entre las aplicaciones del usuario y la base de datos.

  • Nivel externo: Vista externa (Programas de usuario).
  • Nivel conceptual: Esquema Conceptual. Estructura lógica completa (DBA/Diseñador).
  • Nivel interno: Esquema Interno. Estructura física (DBA).

Independencia de Datos y Cliente-Servidor

Cada usuario tiene una vista propia. Existe Independencia Física y Independencia Lógica.
Arquitectura Cliente-Servidor: 2 capas, 3 capas, n-capas. Permite fragmentar los datos: Horizontal, Vertical (¡Causa redundancia!), Híbrida.

1.4 Modelos de Datos

¿Qué es un Modelo?

Resultado de un proceso de abstracción y ayuda a comprender y razonar sobre una realidad. Estructura lógica = Datos + Relaciones. Incluye Operaciones (CRUD) y Restricciones de validación.

Clasificación de Modelos

  • Alto nivel / Conceptual: Muy cercanos al modo en el que el usuario percibe los datos.
  • Implementación / Representación: Entendibles por usuarios. Descubren la estructura lógica, ocultan detalles de implementación. (Red, Relacional, POO, Jerárquico).
  • Bajo Nivel / Físico: Detalles de almacenamiento. Para especialistas (DBA).

2.1 Aspectos Teóricos del Modelo Entidad-Relación

Origen del Modelo E-R

Modelo de datos de alto nivel conceptual. Propuesto por Peter Chen (1976).
Adopta el enfoque más natural del mundo real que consiste en entidades y relaciones.

Entidad e Instancias

  • Entidad: Cualquier objeto que existe en la realidad (Real o Abstracto) y acerca del cual queremos almacenar datos.
  • Tipo de Entidad (Intensión): Estructura genérica que describe un conjunto de entidades.
  • Ejemplar/Entidad (Extensión): Ejemplares de un tipo de entidad.

Reglas de un tipo de Entidad

  1. Tiene que tener existencia propia.
  2. Cada ejemplar debe poder distinguirse de los demás.
  3. Todos los ejemplares deben tener las mismas propiedades.

Categorías de Entidad (Trazado)

Nombre
Fuerte: Tienen existencias por sí mismos.
Nombre
Débil: Depende de que exista un ejemplar de otro tipo de entidad fuerte.

Ejemplos: [Empleado]-[Dependiente], [Dueño]-[Mascota].

2.2 Atributos y Trazados

¿Qué es un Atributo?

Características que describen a las entidades/relaciones. Un ejemplar de atributo es un Valor.

Tipos de Atributos (Gráfica)

  • Simple: Óvalo normal.
  • Compuesto: Óvalo del que salen más óvalos. (Atómico: Expresión mínima).
    • Nombre
    Multivalor: Varios valores permitidos.
    Nombre
    Derivado: Obtenido mediante procesamiento.
    Nombre
    Atributo Llave: Restricción de unicidad (valor distinto para cada ejemplar).
    Nombre
    Atributo Parcial: Llave de la entidad débil.

2.3 Vínculos (Relaciones) y Modelo E-R Extendido

Tipo de Relación vs Relación

Es una asociación entre dos o más tipos de entidades. Se representa con una Acción / Verbo. Hay necesidad de conocer sus atributos llaves de las entidades asociadas.

Categorías de Relación (Con trazado)

Regular: Permite asociar tipos de entidad fuertes.
Identificadora: Asocia una entidad fuerte con una débil (Dependencia directa).

Participación en las Relaciones (Total vs. Parcial)

Define si la existencia de un ejemplar de una entidad requiere obligatoriamente estar vinculado en la relación:

  • Participación Total (Doble línea ═): Todos los ejemplares de la entidad deben participar forzosamente en la relación (Ej: Todo Proyecto debe tener obligatoriamente un Investigador Principal).
  • Participación Parcial (Línea sencilla ─): Es opcional; un ejemplar puede existir sin participar en la relación (Ej: Un Profesor puede no ser Investigador Principal).

2.3.1 Modelo E-R Extendido: Triángulos Amarillos (Especialización / Generalización)

ISA
d
Triángulo Amarillo (ISA / ES_UN): Representa Herencia (Especialización / Generalización). Conecta una Superclase (entidad general arriba) con sus Subclases (entidades específicas abajo).

• Diferencia con Entidad Débil: Una Entidad Débil es un objeto distinto que le pertenece a otro ("Tiene" / HAS-A, como Empleado -> Dependiente). Una Subclase es el mismo objeto pero más específico ("Es un" / IS-A, como Producto -> Medicamento) y hereda la llave primaria (PK) de su superclase.
• Círculo con "d" (Disyunta / Disjoint): Mutuamente excluyente; un ejemplar solo puede pertenecer a una subclase a la vez.
• Círculo con "o" (Solapada / Overlapping): Un ejemplar puede pertenecer a más de una subclase simultáneamente o a través del tiempo.

Recordatorio Clave: Participaciones y Especialización

  • Participación Total (═ Doble línea): Cada ejemplar de la entidad debe participar obligatoriamente en la relación.

Caso 1: Sistema de Líneas de Metro (Visto en clase)

  1. Una línea está compuesta por una serie de estaciones en un orden determinado.
  2. Cada estación pertenece a al menos una línea pudiendo pertenecer a varias.
  3. Una estación nunca deja de pertenecer a la línea a la que originalmente pertenece.
  4. Cada estación puede tener varios accesos pero un acceso solo puede pertenecer a una estación.
  5. Un acceso nunca podrá cambiar de estación.
  6. Cada línea tiene asignado una serie de trenes (un tren no puede estar en más de una línea al mismo tiempo, pero puede no estar asignado si está en reparación).
  7. Algunas estaciones tienen cocheras y cada tren tiene asignada una cochera.

Caso 6: Centro de Investigación (UAM) — Completo con Tabla y Diagrama

El Departamento de Sistemas del Centro de Investigación de la UAM necesita una BD para la gestión de profesores que participan en proyectos de investigación. Requerimientos del sistema:

  1. Proyecto de Investigación: Identificador único, nombre, presupuesto total, programa que lo financia, fecha de inicio, fecha de finalización y descripción.
  2. En los proyectos trabajan profesores durante un período de tiempo determinado por una fecha de inicio y una fecha de fin. Un mismo profesor puede trabajar en el mismo proyecto en diferentes épocas.
  3. Profesores: Identificador único, nombre formado por nombre de pila y apellido paterno (compuesto), despacho y teléfono (multivalor, puede tener más de uno). Pueden ser doctores o no doctores (Especialización).

  5. Investigador Principal (IP): De todos los profesores que trabajan en el proyecto hay uno que es el IP (coordinador), no puede cambiar a lo largo de la vida del proyecto y obligatoriamente tiene que ser un profesor doctor.
  6. Publicaciones: Los profesores doctores y no doctores pueden escribir publicaciones. Tienen un código único y un título, y pueden ser de tipo revista (volumen, número, página de inicio y página de fin) o de congreso (tipo de congreso, ciudad, país, fecha de inicio y fecha de fin).

Caso 7: Farmacia "Los Reyes" — Especialización Multinivel y Promociones

La farmacia "Los Reyes" desea tener una BD para su catálogo de productos, sus proveedores y las promociones que éstos hacen:

  1. Productos: Descritos por código de producto, nombre, descripción y precio. Los productos ofertados son: dulces, cosméticos (su tipo), ópticos (empresa fabricante), medicamentos (grupo terapéutico y principio activo) y aparatos de medición (termómetro, presión, glucosa, oxímetro, etc.).
  2. Tipos de Medicamentos: Pueden ser genéricos (fecha en que se empezaron a considerar como tal) o bajo patente (fecha de patente y duración). Un medicamento no puede ser genérico mientras está bajo patente, pero si la patente ha caducado, podrá aparecer como genérico también.
  3. Laboratorios: Se almacena código de laboratorio, nombre, dirección y teléfono. Fabrican medicamentos y cosméticos, pero solo aquellos considerados laboratorios farmacéuticos (que tienen su correspondiente licencia) tendrán bajo su firma medicamentos (incluidos genéricos). Estos laboratorios farmacéuticos también pueden fabricar cosméticos. Un determinado medicamento o cosmético solo será fabricado por un laboratorio. Interesa conocer qué patentes posee un laboratorio.
  4. Promociones: Los medicamentos tienen precio establecido por ley y los productos de carácter general (aparatos de medición) no aparecen en ninguna promoción. Solo los productos de cosméticos, óptica y dulces pueden ponerse en promoción (fecha de inicio, fecha final y porcentaje de descuento). Cada promoción es realizada por un único proveedor.
  5. Proveedores: Realizan las promociones y distribuyen los productos. Interesa código, nombre, dirección, teléfono y el número de productos distintos que ofrece (derivado). Un producto puede ser servido por varios proveedores y no habrá productos sin proveedor.

1. Identificación de Entidades, Superclases y Subclases

  • PRODUCTO (Superclase Fuerte): Llave Primaria Código_Prod. Atributos: Nombre, Descripción, Precio.
    • Subclases de PRODUCTO (Triángulo ISA Disyunto "d" y Participación Total):
      • DULCE (sin atributos extra, entra en promoción).
      • ÓPTICO (Atributo: Empresa_Fabricante, entra en promoción).
      • COSMÉTICO (Atributo: Tipo, entra en promoción y es fabricado por Laboratorio).
      • APARATO_MEDICIÓN (sin atributos extra, NO entra en promoción).
      • MEDICAMENTO (Atributos: Grupo_Terapéutico, Principio_Activo).
    • Subclases de MEDICAMENTO (Triángulo ISA Solapado "o" por caducidad de patente):
      • GENÉRICO (Atributo: Fecha_Genérico).
      • BAJO_PATENTE (Atributos: Fecha_Patente, Duración).
  • LABORATORIO (Superclase Fuerte): Llave Primaria Código_Lab. Atributos: Nombre, Dirección, Teléfono.
    • LAB_FARMACÉUTICO (Subclase de LABORATORIO): Atributo exclusivo: Licencia. Hereda la capacidad de fabricar cosméticos y es el único que puede firmar medicamentos y poseer patentes.
